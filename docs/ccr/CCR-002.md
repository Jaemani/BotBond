# CCR-002

> 원래 CCR-001로 작성했으나 B의 CCR-001(executable-backend-supporting-types, 2026-08-02 accepted)과 번호 충돌로 CCR-002로 재번호.

- **Requester:** 역할 C (Solana)
- **Affected contract:** docs/03-contracts.md §5 `BondSession` account 구조
- **Current limitation:** PDA seeds가 `["bond", agent, policy_hash, session_nonce]`인데 account에 `session_nonce`가 없다. 이러면 close/settle/reclaim 시 PDA를 재검증하려면 클라이언트가 nonce를 별도 인자로 항상 들고 다녀야 하고, account만 보고 세션을 식별·재파생할 수 없다.
- **Proposed change:** `BondSession`에 `session_nonce: u64` 필드 추가 (`expires_at` 다음, `status` 앞). 후속 instruction들은 저장된 nonce로 seeds 검증을 수행하므로 인자 전달이 불필요해진다.
- **Breaking impact:** account 레이아웃 +8 bytes. 아직 어떤 소비자(B의 bond 상태 확인, A의 표시)도 raw 레이아웃을 파싱하지 않으므로 실질 파급 없음. IDL 경유 접근은 자동 반영.
- **Migration:** 없음 (첫 배포 전 변경).
- **Decision:** Proposed — 팀 확인 대기. 반대 시 nonce를 각 instruction 인자로 되돌리는 대안 있음.
